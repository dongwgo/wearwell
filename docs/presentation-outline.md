# 발표 슬라이드 구성안 (Wearwell)

평가 기준 3축에 맞춘 12장 구성. 각 장의 **한 줄 메시지 → 넣을 내용 → 근거/이미지** 순.

| 평가 축 | 담당 슬라이드 |
|---|---|
| Completeness (impressive/practical/creative) | 1–4, 11 |
| Vision & AI contribution (내가 더한 것, 얼마나 좋아졌나) | 5–9 |
| Understanding (다시 만들 수 있게 설명) | 3, 6, 7, 10 |

---

## 1. 표지 — 무엇을 만들었나

> **전신사진 한 장을 옷장으로 바꾸고, 그 옷을 내 아바타에 입혀본다.**

- 이름/한 줄 소개 + 앱 메인 화면 스크린샷 1장
- 규모: 프런트 **3.7k줄**(랩 도구 1.4k 포함), 백엔드 **4.1k줄**(테스트 별도), API **16개**, 테스트 **129개**, 설계 문서 **4편**
- 🖼 **필요**: 앱 홈 화면 캡처 (`?dev=1` 없이)

## 2. 문제 정의 — 왜 어려운가

> **옷장 앱의 병목은 추천이 아니라 "사진에서 옷을 꺼내는 일"이다.**

- 사용자는 옷을 한 벌씩 찍어 올리지 않는다. 가진 건 **입고 찍은 전신샷**뿐
- 전신샷에서 옷만 꺼내려면: 어디가 옷인지(픽셀) + 무슨 옷인지(속성) + 가려진 데를 어떻게(생성)
- 이 셋은 **서로 다른 종류의 질문**이라 한 모델로 안 된다 → 다음 장

## 3. 아키텍처 — 모델 3개, 서로 다른 질문

> **SegFormer가 오려내고, Qwen이 설명하고, FLUX가 그린다.**

| | 답하는 질문 | 못 하는 것 |
|---|---|---|
| SegFormer | 이 픽셀은 **어느 옷인가** | 소재·핏을 모른다 |
| Qwen3-VL | 이건 **무슨 옷인가** | 픽셀 경계를 못 준다 |
| FLUX.2 | **이렇게 보일 것이다** | 아무것도 판정하지 않는다 |

- GPU 1장 공유: `INFERENCE_GATE`(동시 2), Qwen만 NF4 양자화(8B를 FLUX 워커 2개와 같이 올리려고)
- 📄 근거: [docs/models.md](models.md)

## 4. 데모 시나리오 (라이브 데모 순서표)

> **넣은 사진 → 옷장 → 추천 → 착장, 4분.**

1. 전신샷 업로드 → 옷이 카테고리별로 분리돼 옷장에 들어감
2. 옷 하나 눌러 **Qwen 분석** 실행 → 소재·핏·주름이 채워짐
3. 룩북 고르면 → 내 옷으로 조합된 추천
4. 아바타에 입혀보기 (측면/후면 회전)
- ⚠️ Colab 백엔드 예열 필요(첫 요청 콜드 적재 1~2분) — **데모 전에 워밍업 1회**

## 5. 기여 ① 세그멘테이션 품질 필터 — "없다"고 말하지 못하는 모델 다루기

> **argmax는 모든 픽셀에 반드시 클래스를 준다. 사진에 가방이 없어도 가방을 찾아낸다.**

- 그래서 **면적·채움·확신도 3중 필터**를 따로 만들어 "이 검출을 믿을 수 있나"를 판정
- 임계값은 카테고리마다 다르다 — **품질이 아니라 형태에 대한 가정**이기 때문
  (몸통 0.25 / 신발·가방 0.08)
- 📄 근거: [docs/segmentation.md](segmentation.md)

## 6. 기여 ② 측정으로 찾은 버그 — 신발 검출률 17% → 40%

> **임계값을 하나도 안 건드렸는데 모델 교체만으로 검출률이 반토막 났다.**

| | B2 | B3 |
|---|---|---|
| 면적·채움 통과 신발 후보 | 38개 | **41개** ← 더 잘 찾음 |
| 확신도 0.50 통과 | 38개 | **17개** ← 여기서 죽음 |
| 신발 확신도 중앙값 | 0.751 | **0.487** ← 기준선 바로 아래 |

- 0.42~0.50 구간 23개를 **눈으로 전수 확인 → 전부 진짜 신발**. 오검출이 아니라 캘리브레이션 차이
- B3에만 신발 기준 0.42로 보정 → **17% → 40%**, 확신도 탈락 24건 → 1건
- **교훈: 확신도는 모델에 종속된다.** 면적·채움은 기하학이라 모델 무관, 확신도는 아니다
- 💡 이 장이 "measurement-driven"을 보여주는 핵심 슬라이드

## 7. 기여 ③ Refine 파이프라인 — 세그멘테이션이 남긴 구멍 메우기

> **픽셀당 라벨이 하나뿐이라, 팔이 몸통을 가리면 상의에 구멍이 남는다.**

- 🖼 **`docs/image copy 6.png`** (5단계 화면 — 이 슬라이드의 주인공)
  `세그멘테이션 크롭 → 결함 진단 → 마스크 보수 → 정규화 → FLUX 재생성`
- 핵심 아이디어: **버리던 라벨을 근거로 쓴다.** `Left-arm`은 옷 카테고리가 없어 버려지던
  라벨인데, "여기가 팔에 덮인 자리"라는 증거로 쓰고 그 사실을 **문장으로 만들어** FLUX에 넘김
  > *"About 18% of this garment on its lower left side was covered by the model's left arm…"*
- 보수(형태학)와 생성(FLUX)의 역할 분담: 형태학은 없는 픽셀을 만들지 못한다.
  실루엣을 온전히 만들어 **좋은 입력을 주는 것**까지가 보수의 몫
- 안전장치 실측: 옷이 아닌데 옷이 된 자리 **902px → 0px**, 가려진 옷 복원율 **99.9%**
- 📄 근거: [docs/refine-lab-pipeline.md](refine-lab-pipeline.md)

## 8. 기여 ④ 결과 — Before / After

> **찢어진 크롭이 옷장에 넣을 수 있는 상품컷이 된다.**

- 🖼 **`docs/image_beforerefine.png`** (왼쪽) — 구멍 뚫리고 조각난 크롭
- 🖼 **`docs/image_afterrefine.png`** (오른쪽) — 재생성된 상품컷
- 함께 말할 것: **성별·세그멘테이션 라벨을 프롬프트에 넣은 이유**

  - 실측: 남성 하의 **3벌 전부** 하이웨이스트 큐롯으로 돌아옴 → `gender` + `Pants` 라벨 명시로 해결
  - 카테고리 `하의`는 프롬프트에서 "pants **or** skirt"가 되어 모델이 고르게 된다는 것이 원인

## 9. 기여 ⑤ 프롬프트를 "고칠 수 있게" 만든 도구 3개

> **모델이 틀렸을 때 무엇을 고쳐야 하는지 보이지 않으면 튜닝이 아니라 도박이다.**

| 랩 | 보는 질문 |
|---|---|
| **Seg Lab** | 모델 4종을 같은 사진에 돌려 크롭·탈락 사유·쌍별 IoU 비교 |
| **Refine Lab** | 단계별 중간 산출물을 나란히 (7번 이미지) |
| **Qwen Lab** | **보낸 프롬프트 전문**과 **생성 원문**을 나란히. 필드가 빈 이유가 "확인 어려움"인지 토큰 예산 초과인지 가름 |

- Qwen Lab은 프롬프트를 **백엔드에서 받아온다**(`GET /api/vlm/prompts`). 복사해 두면
  백엔드를 고칠 때마다 탭이 조용히 거짓말을 하기 때문
- 🖼 **필요**: Qwen Lab 실행 화면 캡처 (프롬프트 pane + 원문 pane이 함께 보이게)

## 10. 이해도 — VLM이 뱉은 JSON은 어디로 가나

> **추천 점수의 49%가 색, 20%가 SigLIP 임베딩이다.**

```
total = 0.03 + color×0.49 + material×0.11 + fit×0.10 + detail×0.07 + visual×0.20
```

- **하드 필터가 가중치보다 세다**: `sleeveLength`/`length`/`neckline`이 어긋나면 **총점 0**.
  그래서 프롬프트가 "확인 어려움"을 허용한다 — 모르면 모른다고 해야 필터를 통과한다
- 옷 분석(내 옷)과 룩북 분해(찾아야 할 옷)가 **같은 필드 이름으로 만나** 점수가 된다.
  한쪽 어휘를 바꾸면 반대쪽이 조용히 못 맞춘다
- 📄 근거: [docs/vlm-json-usage.md](vlm-json-usage.md)
- 💡 "다시 만들 수 있나" 질문에 답하는 슬라이드 — 숫자와 실패 모드를 함께 말할 것

## 11. 검증 — 정답 이미지가 없는 태스크를 어떻게 채점했나

> **착장 결과에는 정답이 없어서 SSIM·LPIPS로는 "상의가 아우터 안쪽인가"를 못 잰다.**

- 그래서 **VLM을 심판으로** 세워 이진 판정 → `layering_accuracy`, `item_recall`,
  `identity_preservation` 등 지표화 ([scripts/eval_tryon.py](../scripts/eval_tryon.py))
- 심판 프롬프트는 **근거를 먼저 쓰게** 한다. 결론부터 내라고 하면 첫 토큰에 걸려
  뒤 근거를 결론에 끼워 맞춘다
- 테스트 **129개** (마스크 보수·프롬프트 생성은 GPU 없이 검증 가능하게 분리)

## 12. 한계와 다음 단계 (정직하게)

> **모르는 것을 안다고 말하지 않는 것도 결과다.**

- **세그멘테이션 비교는 정답 라벨이 없다.** 검출률·IoU는 쟀지만 precision·mIoU는 못 쟀다.
  "B3가 낫다"는 판단의 근거 범위를 문서에 명시해 둠
- **기본 옷장 200벌은 상품명 규칙 기반 분석**(`catalog-rules`)을 쓴다. 사진을 안 본 추측값
- **색 정보 공백**: 시드 데이터의 40%가 "색상 다양/미분류" → 색 점수(49%)가 하한에 걸림.
  Qwen `primaryColor`로 메울 수 있는 지점
- 다음: 시드 옷 사전 분석 캐시 배포, 룩북 캐시에 bbox 채우기
