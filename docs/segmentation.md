# 옷 세그멘테이션 — 역할과 임계값 설계

전신샷 한 장에서 입고 있는 옷을 카테고리별 투명 PNG로 잘라내 옷장에 넣는 기능이다.
이 문서는 **이 기능이 무엇을 책임지는지**와 **품질 임계값이 지금 모양이 된 과정**을 남긴다.

관련 코드: [`backend/segment_service.py`](../backend/segment_service.py),
[`backend/segment_models.py`](../backend/segment_models.py),
비교 도구: [Seg Lab 탭](../seg-lab.js), 집계 도구: [`scripts/segment_eval.py`](../scripts/segment_eval.py)

---

## 1. 이 기능이 하는 일과 하지 않는 일

**한다**

- 전신샷에서 옷 픽셀을 찾아 카테고리(상의/하의/원피스/신발/가방/액세서리)로 묶는다
- 카테고리별로 마스크를 알파 채널로 쓴 투명 PNG를 잘라낸다
- 잘라낸 결과물이 옷장에 넣을 만한지 판정하고, 미달이면 버린다

**하지 않는다**

- 옷의 색·소재·핏 분석 — 그건 `Qwen3-VL`이 `/api/vlm/garment`에서 한다
- 사이즈 판정이나 체형 추정 — 별개 기능이다
- 브랜드·상품 식별

- 잘라낸 마스크의 구멍 메우기나 상품컷 변환 — 그건 [`backend/refine_service.py`](../backend/refine_service.py)와
  FLUX가 맡는다 (README의 "Refine Lab" 절, [Refine Lab 탭](../refine-lab.js))

즉 세그멘테이션은 **"어디까지가 옷인가"만 답하는 단계**다. 그 뒤 분석은 전부 다른 모델이 맡는다.
이 경계가 중요한 이유는, 세그멘테이션이 애매한 결과를 옷장에 흘려보내면 그 오염이
VLM 분석과 코디 추천까지 그대로 전파되기 때문이다. 그래서 **버리는 판단**이 이 기능의 절반이다.

---

## 2. 파이프라인

```
전신샷
  → SegFormer 추론 (logits)
  → 원본 해상도로 bilinear 업샘플
  → softmax → 픽셀별 확신도 / argmax → 픽셀별 클래스
  → 라벨을 옷장 카테고리로 매핑, 같은 카테고리는 마스크 합침
  → 3중 품질 필터 (면적 / 채움 / 확신도)   ← 이 문서의 주제
  → 10px 여유를 두고 크롭, 마스크를 알파로 넣어 RGBA PNG
```

**마스크를 합치는 이유**: ATR 라벨은 신발을 `Left-shoe`/`Right-shoe`로 나눈다.
합치지 않으면 신발 한 켤레가 옷장에 두 벌로 등록된다.
([`_category_masks`](../backend/segment_service.py#L136-L155))

**매핑되지 않은 라벨도 버리지 않는다**: `Left-arm`, `Hair`, `Bag`은 옷장 카테고리가
없어 여기서 빠지지만, `analyze()`는 라벨맵 원본을 `_parse`로 함께 싣는다. "이 빈 자리가
배경인지 팔에 덮인 옷인지"를 가르는 근거가 그 라벨뿐이기 때문이다 —
[refine-lab-pipeline.md](refine-lab-pipeline.md)의 2단계 가림 판정이 이걸 쓴다.

---

## 3. 왜 임계값 단계가 필요한가

**semantic segmentation 모델은 "없다"고 말하지 못한다.** argmax는 모든 픽셀에
반드시 어떤 클래스를 배정한다. 사진에 가방이 없어도 모델은 가방 확률이 가장 높은 픽셀
몇 개를 어딘가에서 찾아낸다. 그래서 모델 출력을 그대로 믿으면 옷장이 쓰레기로 찬다.

임계값 단계는 **"이 검출을 믿을 수 있는가"**를 판정한다. 여기서 탈락한다는 건
"사진에 그 옷이 없다"가 아니라 **"이번에 잘라낸 결과물을 쓸 수 없다"**는 뜻이다.

세 축을 쓰는 이유는 각각 **다른 실패 유형**을 잡기 때문이다.

| 축 | 계산 | 잡는 실패 |
| --- | --- | --- |
| **면적** | 마스크 픽셀 / 전체 픽셀 | 조각만 잡힘, 배경·행인 오검출 |
| **채움** | 마스크 픽셀 / 바운딩박스 넓이 | 마스크가 흩어짐 → 크롭이 대부분 투명 |
| **확신도** | 마스크 픽셀의 max softmax 평균 | 모양은 멀쩡, 분류가 애매 |

축 하나로는 안 된다. 면적만 보면 흩어진 마스크가 통과해 빈 PNG가 나오고,
채움만 보면 작은 얼룩이 통과한다. 확신도는 앞의 둘과 독립이라 **모양은 완벽한데
모델이 헷갈리는 경우**를 따로 잡아야 한다.

## 4. 임계값 시행착오

### 1차 — 모든 카테고리에 같은 채움 기준 (0.28)

가장 자연스러운 출발점이었고, **틀렸다.**

무신사 스냅 100장에서 재현한 결과 (`--fixed-fill 0.28`, b3_clothes):

| 카테고리 | 카테고리별 기준 | 단일 기준 0.28 |
| --- | --- | --- |
| 상의 | 90% | 89% |
| 하의 | 68% | 67% |
| **신발** | **40%** | **31%** |
| **가방** | **19%** | **13%** |

상의·하의는 멀쩡한데 신발과 가방만 무너진다.
(저장소에 남아 있던 이전 데이터셋 실측 기록은 더 극단적이다 — 신발 56%→9%, 가방 36%→8%.)

**원인은 형태다.** 채움 비율의 분모는 마스크를 감싸는 사각형인데,

- 상의·하의·원피스는 몸통을 덩어리로 덮어서 사각형을 잘 채운다 (실측 53~61%)
- **신발은 왼발+오른발 마스크를 합치므로** 사각형이 두 발을 다 감싸고, 그 사이 빈 공간이
  전부 분모에 들어간다 (실측 27~31%)
- 가방·액세서리는 끈처럼 가늘어서 대각선으로 놓이면 사각형의 대부분이 빈 공간이다

즉 **낮은 채움 비율이 신발·가방에서는 정상**이다. 단일 기준은 이 카테고리들을
품질과 무관하게 통째로 걸러낸다.

### 2차 — 카테고리별 채움 기준

형태가 다르면 기준도 달라야 한다. 몸통 계열은 0.25, 신발·가방은 0.08,
액세서리는 0.08로 나눴다. ([`QUALITY_THRESHOLDS`](../backend/segment_models.py))

이 구조가 지금까지 유지되고 있다. **교훈: 임계값은 "품질"이 아니라 "형태"에 대한
가정을 담고 있다.** 가정이 카테고리마다 다르면 기준도 갈라야 한다.

### 3차 — 모델별 확신도 보정

프로덕션 모델을 B2에서 B3로 갈아타면서 드러난 문제다. **임계값을 하나도 건드리지
않았는데 신발 검출률이 38% → 17%로 반토막 났다.**

원인을 축별로 분해해 보니 명확했다.

| | B2 | B3 |
| --- | --- | --- |
| 면적·채움을 통과한 신발 후보 | 38개 | **41개** |
| 그중 확신도 0.50 기준 통과 | 38개 | **17개** |
| 신발 확신도 중앙값 | 0.751 | **0.487** |

**B3는 신발을 더 잘 찾는다** (후보 41 > 38). 문제는 확신도 분포가 통째로 낮게
잡히고, 그 중앙값 0.487이 기존 기준 0.50 **바로 아래**에 앉아 있다는 것이다.
기준선이 분포를 정확히 반으로 자르고 있었다.

0.42~0.50 구간에 걸린 23개를 눈으로 확인한 결과 **전부 실제 신발이었다** —
로퍼, 스니커, 부츠, 샌들. 오검출이 아니라 캘리브레이션 차이였다.

그래서 B3에만 신발 확신도 기준을 0.42로 낮췄다.

```python
threshold_overrides={"신발": {"minConfidence": 0.42}},
```

결과: 신발 17% → **40%**, 확신도 탈락 24건 → 1건.

**교훈: 확신도 임계값은 모델에 종속된다.** softmax 값은 모델마다 다르게 캘리브레이션되어
있어서, 같은 숫자가 모델이 바뀌면 다른 의미가 된다. 면적·채움은 기하학이라 모델과
무관하지만 확신도는 그렇지 않다. 그래서 기준을 전역 상수에서 **모델 스펙에 붙는
보정값**으로 옮겼다 ([`ModelSpec.thresholds_for`](../backend/segment_models.py)).
보정은 **지정한 키만 덮고 나머지 축은 기본값을 유지**한다 — 통째로 갈아끼우면
보정 하나 넣을 때마다 나머지 두 축이 조용히 사라진다.

## 5. 프로덕션 모델 — `sayeed99/segformer_b3_clothes`

B2에서 B3로 교체했다. 라벨 체계(ATR 18클래스)가 같아 매핑 코드는 그대로다.

### 근거

**① 주요 카테고리의 확신도가 일관되게 높다** (100장 평균)

| | B2 | B3 |
| --- | --- | --- |
| 상의 | 0.898 | **0.907** |
| 하의 | 0.824 | **0.845** |

**② 신발 마스크의 형태가 더 온전하다** — 면적·채움을 통과한 후보가 41개로 B2(38개)보다 많다.
확신도 기준을 맞춘 뒤 최종 검출률도 40% > 38%.

**③ 검출률이 전 카테고리에서 동률 이상** (임계값 보정 후, 100장)

| 카테고리 | B2 | B3 |
| --- | --- | --- |
| 상의 | 90% | 90% |
| 하의 | 69% | 68% |
| 원피스 | 3% | 4% |
| 신발 | 38% | **40%** |
| 가방 | 20% | 19% |
| 액세서리 | 8% | 8% |

하의·가방의 1%p 차이는 100장 표본에서 1장 차이라 유의미하지 않다.

**④ 인코더가 크다** — MiT-B3(189MB) vs MiT-B2(110MB). 두 모델의 카테고리 IoU는
상의 0.964 / 하의 0.936으로 대체로 같은 판단을 하며, **차이는 경계 품질에서 난다.**

### 비용

추론 시간이 늘고(GPU 웜 기준 체감 차이는 작다) 가중치가 79MB 크다.
로컬 CPU로 돌릴 때는 이 차이가 더 벌어진다.

## 7. 재현 방법

**여러 장 집계** — 임계값이나 모델을 바꿨을 때 검출률이 어떻게 변하는지

```bash
python scripts/segment_eval.py <사진폴더> --models b2_clothes,b3_clothes
python scripts/segment_eval.py <사진폴더> --models b3_clothes --fixed-fill 0.28
```

카테고리별로 통과 수와 **어느 축에서 탈락했는지**를 함께 센다. 검출률만 보면
"왜 떨어졌는지"를 알 수 없어서, 병목 축을 찾는 게 이 도구의 목적이다.

**한 장 심층 비교** — Seg Lab 탭 (`http://127.0.0.1:8000` → Seg Lab)

모델별 오버레이, 걸러진 후보와 탈락 사유, 매핑되지 않은 원본 라벨, 모델 쌍별 IoU를
나란히 본다. 실행법은 [README의 Seg Lab 절](../README.md) 참고.

## 8. 측정하지 않은 것

**이 문서의 숫자는 전부 검출률이지 정확도가 아니다.** 정답 마스크가 없어서
precision이나 mIoU를 측정하지 못했다. "B3가 더 낫다"는 판단은

- 확신도 평균 비교
- 면적·채움을 통과한 후보 수
- 0.42~0.50 구간 신발 크롭 23개 육안 확인
- 인코더 규모

에 근거한 것이며, **정량적 정확도 비교가 아니다.** 오검출률이 함께 올랐을 가능성은
배제하지 못했다.

제대로 하려면 ATR 검증셋이나 직접 라벨링한 표본에 대해 카테고리별 IoU를 재야 한다.
지금 구조에서는 `scripts/segment_eval.py`에 정답 마스크 경로를 받는 인자를 더하면 된다.

또한 평가에 쓴 무신사 스냅 100장은 **5:6으로 균일하게 크롭된 사진**이라 발끝이
잘린 것이 섞여 있다. 신발 검출률 40%라는 절대값은 이 데이터셋 특성이 섞인 값이므로,
**모델 간 비교에는 쓸 수 있어도 실제 서비스 검출률의 추정치로 읽으면 안 된다.**

## 9. 다음에 건드릴 때

- **모델을 바꾸면 확신도 기준을 반드시 다시 잰다.** 면적·채움은 기하학이라 그대로
  써도 되지만 확신도는 아니다. `segment_eval.py`로 축별 탈락 분포부터 본다.
- **검출률이 떨어졌다고 임계값부터 낮추지 않는다.** 후보 수(면적·채움 통과)와
  최종 통과 수를 나눠 봐야 "못 찾은 것"과 "찾고도 버린 것"이 구분된다. 3차 시행착오가
  정확히 이 구분에서 풀렸다.
- **임계값은 현재 백엔드 상수라 바꾸려면 재시작이 필요하다.** 반복 실험이 잦아지면
  Seg Lab에서 슬라이더로 조정할 수 있게 요청 파라미터로 빼는 것이 낫다.
