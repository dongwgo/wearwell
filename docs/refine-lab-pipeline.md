# Refine Lab 파이프라인 정리

전신샷 한 장에서 옷을 잘라내고, 망가진 마스크를 보수한 뒤, FLUX로 옷장용 상품컷을 재생성하는 전체 흐름.

> 관련 코드: `backend/app.py` (`/api/closet/refine`), `backend/refine_service.py` (2~4단계),
> `backend/segment_service.py` (`analyze`가 `_parse` 라벨맵을 함께 싣는다),
> `refine-lab.js` (프론트 탭), `scripts/refine-lab-test.mjs` (E2E)

---

## 왜 이 파이프라인이 필요한가

세그멘테이션 argmax는 픽셀마다 라벨을 **하나만** 준다:

| 문제 | 원인 | 결과 |
|---|---|---|
| 구멍 | 팔·머리카락이 몸통 **안쪽**을 가림 | 상의 마스크에 둘러싸인 빈 자리 |
| 파먹힘(가림) | 팔이 옷을 **가로질러** 바깥까지 이어짐 | 실루엣이 만(灣)처럼 베임 — 구멍이 아니다 |
| 조각 분리 | 가방 끈, 겹쳐 입은 옷에 가려짐 | 한 벌이 여러 조각으로 끊김 |
| 부스러기 | 경계 오검출 | 점 같은 쓰레기 조각 |

두 번째 줄이 가장 흔하면서 가장 오래 안 보이던 결함이다. 바깥과 이어져 있어서
`find_holes`가 못 세고(구멍 0개로 나온다), 닫기 커널을 팔 굵기만큼 키우면 옷 모양이
뭉개진다. 그래서 판정을 **형태가 아니라 라벨**로 한다 — 세그멘테이션은 그 팔을 이미
`Left-arm`으로 찍어 놓았고, 옷 볼록껍질 안에서 사람 픽셀에 덮인 자리는 배경이 아니라
가려진 옷이다.

그래도 보수가 만드는 건 **실루엣까지다.** 그 안의 질감·주름·무늬를 실제로 그리는 것은
FLUX의 몫이다. 그래서 두 단계가 모두 필요하다.

## 5단계 파이프라인

```
전신샷
 │
 ├─ 1. 세그멘테이션   SegFormer b3 (기본값), 카테고리별 마스크 + 품질 필터
 │
 └─ 옷 한 벌마다 (요청당 최대 MAX_REFINE_ITEMS=4벌):
     │
     ├─ 2. 결함 진단      구멍·가림·조각·부스러기를 센다
     ├─ 3. 마스크 보수    닫기 → 구멍 메우기 → 가림 메우기 → 다듬기 → 부스러기 제거
     ├─ 4. 정규화         메운 자리에 경계색을 전파하고 흰 배경 768×768로
     └─ 5. FLUX 재생성    가려졌던 질감·주름을 그려낸다 (GPU 필요)
```

### 1단계 — 세그멘테이션
- 모델: `sayeed99/segformer_b3_clothes` (ATR 18 라벨, 프로덕션 기본값)
- 품질 필터: 면적·채움(fillRatio)·확신도 기준으로 후보 통과/탈락 결정
- `includeRejected=true`면 걸러진 후보도 파이프라인에 태움 (왜 걸러졌는지 생성 결과로 검증)
- 요청의 `categories` 칩으로 처리 대상 좁히기 가능

### 2단계 — 결함 진단 (`diagnose` + `find_occluded`)
마스크 상태를 숫자로 남긴다:

| 지표 | 의미 |
|---|---|
| `holeCount` / `holeRatio` | 구멍 개수 / 비율 (분모 = 옷이 온전했을 넓이) |
| `occludedPixels` / `occludedRatio` | 가려져 파먹힌 넓이 (구멍은 제외 — 두 번 세지 않는다) |
| `occludedBy` | 무엇이 가렸는지 상위 3개 (`Left-arm 71%` 꼴) |
| `occludedWhere` | 가려진 자리 (`lower-left` 등, 프롬프트에도 그대로 쓰인다) |
| `solidity` | 볼록껍질을 얼마나 채우는가. 구멍이 없어도 파먹혔으면 떨어진다 |
| `componentCount` | 조각 수 |
| `strayCount` / `strayRatio` | 최대 조각 대비 8% 미만 부스러기 수/비율 |
| `fillRatio` | 크롭 안에서 옷이 차지하는 비율 |

**가림 판정(`find_occluded`)** — 네 겹으로 좁힌다:

1. **볼록껍질 안쪽** (`convex_hull_mask`): 팔 전체가 아니라 옷을 가로지르는 토막만 남는다
2. **테두리 60% 이상이 옷에 닿을 것** (`occlusionEnclosure`): 옷 옆에 나란히 있을 뿐인
   팔은 테두리가 배경에 닿으므로 제외된다. 크롭 밖으로 나가는 면은 배경으로 센다
3. **조각 하나가 옷 면적의 35% 이하일 것** (`OCCLUSION_MAX_RATIO`): 통 넓은 바지에 덮인
   부츠처럼 마스크가 바짓단을 삼키는 조합을 막는다. 걸린 조각은 버리지 않고
   `oversizedCount`로 남긴다 — 기준을 실측으로 고치기 위해
4. **옷이 가로나 세로 양쪽에 남아 있을 것** (`_bracketed`): 소매와 허리 사이처럼 원래
   파인 자리를 껍질이 가로지르는데, 거기 팔이 지나가면 1~3을 다 통과해 버린다. 통과한
   조각 안에서 이 조건까지 만족하는 자리만 메운다 (합성 검증: 옷이 아닌데 옷이 된 자리 902px → 0px, 가려진 옷 복원율 99.9%)

판정 순서가 중요하다 — 3번까지는 **조각 통째로**, 4번은 **그 조각 안에서** 판정한다.
먼저 잘라 놓고 2번을 재면 잘라낸 단면이 "배경에 닿은 테두리"로 세어져 멀쩡한 조각이 탈락한다.

`_parse`(세그멘테이션 라벨맵)가 없으면 이 판정 전체가 빠진다(`occlusionAvailable: false`).
형태만 보고 메우면 진짜 옷 경계까지 부풀기 때문에, 근거가 없으면 아예 하지 않는다.

시각화: **구멍=빨강, 가려짐=주황, 버릴 조각=파랑**, 나머지 배경은 어둡게

### 3단계 — 마스크 보수 (`repair`)
순서대로 실행, 각 단계 UI에서 끄고 켤 수 있음:

1. **닫기(close)**: MaxFilter→MinFilter (팽창 후 침식). 커널 = 크롭 짧은 변 × 1.2%, 최대 21px.
   키우면 옷 모양이 뭉개짐
2. **구멍 메우기(fillHoles)**: 바깥과 이어지지 않는 빈 영역만 골라 채움
   (반전 후 테두리에 닿는 성분 = 배경으로 제외해야 진구멍만 남음)
3. **가림 메우기(fillOccluded)**: 2단계가 확정한 영역을 합침. 팔에 끊겼던 자락이 다시
   붙으므로 `componentsAfter`가 대개 1로 떨어진다
4. **경계 다듬기(smooth)**: 3px 중앙값 필터. 가림을 메우면 경계에 팔 실루엣 모양 톱니가
   남는다. 마스크의 3%를 넘게 깎으면 되돌린다 — 목걸이 줄처럼 가는 것이 통째로 사라진다
5. **부스러기 제거(dropStrays)**: 최대 조각 대비 8% 미만 제거.
   "가장 큰 것만 남기기"가 아닌 이유 — 신발은 두 조각이 정상

결과 리포트: `pixelsBefore/After`, `growth`, `componentsAfter`, `holesAfter`, 단계별 delta,
`occlusion`(후보/적용/보류 내역)

### 4단계 — 정규화 (`normalize`)
- 새로 메운 자리(`after & ~before`)에 **옷 경계의 색을 전파**(`patchFill: propagate`)
  - 알파로만 채우면 그 자리의 살색·배경 픽셀이 남고, FLUX가 그걸 옷의 일부로 읽음
  - 대표색 한 가지로 평평하게 칠하면 FLUX가 그 자리를 "무지 패널"로 읽음. 경계에서
    색을 이어받으면 팔 아래 그림자·명암이 끊기지 않아 채울 일이 질감·주름으로 좁아짐
  - 축소판(긴 변 192px)에서 확산시킨 뒤 되키운다 — 필요한 건 정확한 픽셀이 아니라
    이어지는 명암이고, 원본 해상도로 수백 번 돌리면 랩 응답이 눈에 띄게 느려진다
  - 전파가 불가능하면(옷 픽셀이 없을 때) 중앙값 색으로 떨어진다 (`patchFill: median`)
- **경계**: 옷 색을 바깥으로 2px 번지게 한 뒤 알파를 0.8px 흐림. 이진 알파를 흰 배경에
  얹으면 계단이 남고, 번지게 하지 않고 흐리기만 하면 마스크 바깥의 살색이 후광으로 섞인다
- 투명 크롭 → **흰 배경 768×768 정사각** (여백 6%). 알파를 흰색으로 깔지 않으면 투명영역이
  검게 읽혀 모델이 검은 면을 옷으로 그림
- 스테이지 미리보기 이미지는 460px로 축소해 응답 (원본 해상도 연산, 응답만 축소)

### 5단계 — FLUX 재생성 (`FluxImageEngine.refine_garment`)
- 모델: **FLUX.2-klein-4B** (아바타·착장과 동일 엔진 공유, 첫 호출 때 적재 — 몇 분 소요)
- 입력: 정규화 이미지 1장 → 출력: 768×768 상품컷 (`REFINE_WIDTH/HEIGHT`)
- 프롬프트 핵심: "구멍을 메우고 끊어진 조각을 잇되 **색·패턴·재단·비율은 절대 유지**"
  자유롭게 그리라고 하면 다른 옷이 나옴
- 2단계 진단이 한 문장으로 붙는다 (`generation_hint`, 가려짐 2% 이상일 때만):
  *"About 18% of this garment on its lower left side was covered by the model's left arm…"*
  어디가 왜 비었는지 말해 주지 않으면 모델은 평평한 색면을 무지 패널로, 파먹힌 실루엣을
  원래 디자인으로 읽는다
- **성별과 원본 라벨이 프롬프트에 들어간다.** 빼면 모델이 상품컷 기본값인 여성복 재단으로
  그린다 — 실측으로 남성 하의 3벌이 전부 하이웨이스트 큐롯·테이퍼드로 돌아왔다.
  두 가지를 고친다:
  - 카테고리 대신 **세그멘테이션 라벨**로 옷 이름을 만든다. `하의`는 카테고리 이름이
    "pants **or skirt**"라 모델이 둘 중 하나를 고르게 된다. 세그멘테이션은 이미 `Pants`라고
    말하고 있으므로 그걸 쓴다(`garment_noun`). `Skirt+Pants`처럼 합쳐져 확정할 수 없으면
    카테고리로 돌아간다 — 치마일 수도 있는 걸 바지라고 단정하면 반대로 틀린다
  - `gender`가 오면 재단을 한 문장으로 못 박는다(`GENDER_CUT`). 없으면 최소한
    "레퍼런스와 다른 재단으로 바꾸지 말라"고만 건다
- 시드 고정(`seed`, 기본 42)으로 재현성 확보, `steps` 지정 가능 (1–50)
- GPU 없으면: `refine-passthrough-fallback` — 정규화본을 그대로 768×768 리사이즈해 반환
  (구멍은 남지만 4단계까진 GPU 없이 검증 가능). **이 경로에서는 `steps`가 무시된다** —
  로컬에서 스텝만 바꿔가며 비교해도 결과가 같다
- 옷 한 벌마다 FLUX 1회 → 요청당 최대 4벌. 개별 실패 허용 (`generationError`),
  한 벌 실패해도 나머지 결과는 반환

#### steps를 4로 두는 이유

klein은 **4스텝 증류 모델**이다. 수십 스텝 걸리던 디노이징 궤적을 4스텝에 착지하도록
학습시킨 버전이라, 스텝은 "올릴수록 좋아지는" 손잡이가 아니다. `FLUX_GUIDANCE`도 1.0으로
꺼 두었다 — 증류 모델은 guidance가 내장되어 있어 CFG를 켜도 얻는 것이 없고, 따라서
**스텝을 올려도 CFG로 인한 개선이 없다.**

| steps | 예상 시간¹ | 결과 |
|---|---|---|
| 1–2 | 0.2–0.4s | 형태가 뭉개진다. 로고·프린트가 흐려지고 실루엣이 흔들린다 |
| **4** (기본) | 0.76s | 증류 목표점. 옷 한 벌 재생성에는 이게 설계값 |
| 6–8 | 1.1–1.5s | 질감·주름이 붙는 구간. 메운 자리가 평평하게 나올 때 여기부터 시도 |
| 12–20 | 2.3–3.8s | 개선폭이 거의 멈춘다. 대신 원본에서 멀어질 여지만 커진다 |
| 30–50 | 5.7–9.5s | 증류 목표를 한참 넘는다. 채도·대비가 밀리거나 옷을 "다시 상상"하기 시작 |

¹ 4스텝 실측 0.76s 기준 선형 환산. 구간별 화질은 실측이 아니라 모델 특성에서 나온 예측이다.

두 가지가 특히 중요하다:

- **스텝을 바꾸면 시드 고정이 무의미해진다.** `seed 42 · 4steps`와 `seed 42 · 8steps`는
  "같은 그림에 디테일이 더 붙은 것"이 아니라 **서로 다른 그림**이다(샘플링 궤적이 달라진다).
  랩에서 A/B 할 때 스텝만 바꿔 놓고 같은 옷이 나오리라 기대하면 안 된다
- **스텝이 높을수록 옷이 바뀔 위험이 커진다.** 이 경로의 목적은 재생성이 아니라 **복원**이라
  트레이드오프 방향이 일반적인 이미지 생성과 반대다. 스텝을 늘리는 건 모델에게 참조에서
  벗어날 자유를 더 주는 것과 같고, 프롬프트가 막으려는 것이 바로 그것이다

**언제 올리나**: 4단계가 메운 자리(가려졌던 자락)가 결과물에서도 여전히 평평한 색면으로
남을 때. 없던 질감을 지어내는 일이라 4스텝으로 모자랄 수 있다. 반대로 색·재단이 바뀌어
나오면 스텝이 과한 것이다. 착장(try-on)이 `FLUX_TRYON_STEPS=8`을 쓰는 것도 같은 이유 —
스텝을 올려 화질을 얻으려는 게 아니라, 참조가 5~7장으로 늘어 4스텝에서 레이어가 뭉개지기
때문이다.

## API

`POST /api/closet/refine` — 공개 경로 (dev 도구 꺼져 있어도 동작)

```jsonc
{
  "image": "<data URL 또는 base64>",   // 필수
  "name": "full-body photo",           // 프롬프트용 이름
  "model": null,                       // 세그멘테이션 모델 key (null=b3 기본값)
  "categories": [],                    // 비우면 통과한 카테고리 전부
  "includeRejected": false,
  "gender": "men",                     // men | women | null (null이면 중립 지시만)
  "repair": {                          // RepairOptions
    "close": true, "closeScale": 0.012,
    "fillHoles": true,
    "fillOccluded": true, "occlusionEnclosure": 0.6,
    "smooth": true,
    "dropStrays": true, "strayRatio": 0.08
  },
  "generate": true,                    // false면 4단계까지만 (GPU 불필요)
  "seed": 42,
  "steps": null                        // null = 백엔드 기본 FLUX_STEPS(4)
}
```

응답: 옷 한 벌당 `stages: {crop, defects, repaired, normalized, closet}` data URL +
`diagnosis`(진단 수치 + 가림 지표) + `repair`(보수 리포트 + `occlusion`, `patchFill`) +
`generation`(engine/seed/seconds) or `generationError`. 공통: `model, device,
segmentSeconds, loadSeconds, overlay, detectedCount, skippedCount, totalSeconds`

참고: 모델 목록·카테고리 색은 `GET /api/closet/models` (상수 응답).
Seg Lab 전용 비교는 여전히 `/api/dev/*` (`WEARWELL_DEV_TOOLS=1` 필요).

## 환경 변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `REFINE_WIDTH` / `REFINE_HEIGHT` | 768 / 768 | 생성 해상도 (정사각 권장 — 아바타용 768×1152는 옷을 세로로 늘림) |
| `FLUX_STEPS` | 4 | 요청에 `steps`가 없을 때 쓰는 값. klein의 증류 목표점이라 올릴 이유가 거의 없다 (위 표 참고) |
| `FLUX_GUIDANCE` | 1.0 | 증류 모델이라 CFG를 끈 상태. 올려도 스텝 대비 이득이 없다 |
| `MAX_REFINE_ITEMS` | 4 | 요청 1회당 재생성할 옷 최대 수 |
| `WEARWELL_DEV_TOOLS` | 0 | `/api/dev/*` 노출 여부. Refine Lab은 이 값과 무관하게 동작 |
| `ONEULOUT_GPU` | 1 | 0이면 FLUX 대신 passthrough fallback |

## 백엔드 선택 로직 (프론트)

- Refine Lab은 **Colab GPU(API_BASE)가 기본** — 5단계에 GPU가 필요하기 때문
- Seg Lab은 로컬이 기본 (세그멘테이션만 하므로). 두 탭은 주소를 따로 기억
- 주소별 토큰 자동 매핑: Colab=`API_TOKEN`, 로컬=`LOCAL_API_TOKEN`
- 헬스 배지가 원인 구분: `dev 도구 꺼짐` vs `구버전 백엔드(라우트 없음)` vs `토큰 불일치`
- 공개 경로(`/api/closet/*`) 우선 → 없는 예전 백엔드에서만 dev 경로로 폴백

## Colab에서 쓰려면 (중요)

노트북은 **main 브랜치만** `git pull --ff-only`로 받는다. 따라서:

1. `segmentation` 브랜치 내용이 main에 머지·push 되어야 함
   (`refine_service.py`, `/api/closet/refine` 라우트가 현재 main에는 없음)
2. Colab 노트북 **셀 2~3 재실행**으로 코드 갱신 + 서버 재시작
3. 첫 FLUX 호출 때 가중치 적재로 몇 분 걸리는 것은 정상
